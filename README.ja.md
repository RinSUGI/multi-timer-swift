# Multi Timer

[English](README.md) | **日本語**

> [!IMPORTANT]
> **このプロジェクトは、実装を100% AIエージェントに委ねたAI駆動開発のポートフォリオです。**  
> ソースコード、テスト、設計ドキュメント、開発・配布用スクリプトはAIが作成しています。オーナー自身が手書きしたコードを成果として示すものではなく、AIへ要件と制約を与え、出力を検証し、動くアプリとして完成させる能力を示すことを目的としています。

複数のカウントダウンを同時に管理できる、macOS向けのネイティブタイマーアプリです。

## AI駆動開発について

### 使用したAI

- **Claude（Opus 4.7）**: 主な実装エージェント。会話履歴に依存せず作業できる詳細プランに沿って、設計、Swift実装、テスト、ビルド・配布の各フェーズを進行
- **OpenAI Codex**: リポジトリを直接確認しながら、ルールに沿った保守、レビュー、ドキュメント改善、検証を支援

### 人間とAIの役割分担

| 人間（オーナー）                           | AIエージェント                                     |
| ------------------------------------------ | -------------------------------------------------- |
| 作りたい体験、要件、優先順位、制約を決める | 設計案、実装計画、コード、テスト、文書を作成する   |
| 曖昧な仕様やトレードオフを判断する         | 既存仕様を調査し、選択肢、影響、リスクを示す       |
| 実機で挙動を確認し、成果物を受け入れる     | ビルドと自動テストを実行し、結果と残課題を報告する |
| コミット、マージ、リリースを承認する       | 明示的な許可の範囲内でリポジトリを操作する         |

AIに「アプリを作って」と一括で任せるのではなく、[要件・仕様・設計](docs/design-docs/README.md)を会話より優先する正本として整備し、[フェーズ別の実装計画](docs/plans/README.md)と完了条件に分解しました。これにより、エージェントや会話が変わっても同じ前提から作業を再開でき、判断の揺れや場当たり的な実装を抑えています。

### AIを制御する仕組み

- **仕様による制御**: 実装前に期待する振る舞い、対象外、依存方向、データ形式を文書化し、矛盾した場合は設計書を優先
- **小さな完了単位**: Core、永続化、Platform、UI、アプリ結線、配布の順に分割し、前フェーズの検証完了後に次へ進行
- **権限の境界**: コミット、push、PR、`dev`から`main`への反映はAIが独断で行わず、人間の明示指示とレビューを必須化
- **状態の可視化**: 実装タスクとテストケースの状態を[進捗管理JSON](docs/plans/progress-list.json)で追跡し、未完了やブロックを隠さない

### 品質を担保する仕組み

- **テストしやすい設計**: UIやOS機能から純粋ロジックを分離し、時刻、保存先、通知、音を差し替え可能にして、AIの実装を決定論的に検証
- **要件とテストの対応付け**: 時刻変換、入力補正、状態遷移、通知文言、永続化など73項目のテストケースIDを実装フェーズへ割り当て、`swift build`と`swift test`を完了条件に設定
- **文書も機械検証**: Prettier、markdownlint、textlint、shfmt、ShellCheckをまとめた`./scripts/agent-docs-check.sh`で、AIが生成した文書とスクリプトを検査
- **人間による最終確認**: 自動化しにくいUI、通知、音、ウィンドウ操作は、11のブラックボックステストと3つの非機能確認を実機で受け入れ

詳しい運用は[開発ワークフロー](docs/WORKFLOW.md)、テストの考え方は[テスト戦略](docs/design-docs/60-testing/strategy.md)を参照してください。

## 主な機能

- 最大12個のタイマーを個別に開始、停止、リセット、クリア
- `HH:MM:SS`の各セグメントを直接編集（最大`99:59:59`）
- タイマーごとのタイトル設定、追加、削除
- 終了時のチャイム音とmacOS通知
- 終了したタイマーの黄色表示と設定時間への自動リセット
- タイトルと設定時間の自動保存、再起動時の復元
- ウィンドウサイズに合わせたUIの縮小と縦スクロール
- Apple SiliconとIntel Macに対応するUniversal配布

詳細な振る舞いは[機能要件](docs/design-docs/10-requirements/functional.md)と[仕様書](docs/design-docs/README.md)を参照してください。

## 動作環境

- macOS 13 Ventura以降
- 開発時はSwift 5.9以降を利用できるXcodeまたはXcode Command Line Tools

アプリ本体はmacOSの標準フレームワークだけで動作し、ネットワーク通信やテレメトリは行いません。

## インストール

配布された`Multi Timer-<version>-universal.dmg`を開き、`Multi Timer.app`を`Applications`フォルダへドラッグしてください。

現在の配布物はアドホック署名のため、初回起動時にmacOSの許可操作が必要です。チェックサムの確認方法を含む詳しい手順は[インストール手順](docs/インストール手順.md)を参照してください。

タイマー終了時の通知を使うには、初回起動時にmacOSの通知を許可します。許可しない場合も、タイマーとチャイム音は動作します。

## 基本操作

1. 時、分、秒の数字をクリックして時間を入力します。
2. 必要に応じてタイトルを編集します。
3. `Start`でカウントダウンを開始します。
4. `Stop`、`Reset`、`Clear`でタイマーを操作します。

画面下部の`+`でタイマーを追加し、タイトル右側の赤い`×`で削除できます。

## 開発

### アプリの起動

リポジトリのルートで次を実行します。

```bash
./scripts/run-dev.sh
```

このスクリプトはデバッグビルドを`.app`へまとめ、通常のmacOSアプリとして起動します。`swift run multi-timer`は実行ファイルを直接起動するため、ウィンドウが前面に表示されない場合があります。

### テスト

```bash
swift test
```

自動テストは、時刻変換、状態遷移、入力値の正規化、保存データの読み書きなどを対象としています。UI、通知、音、ウィンドウ操作は[ブラックボックステスト](docs/design-docs/60-testing/blackbox-test-guide.md)で確認します。

### ドキュメントの検証

初回だけNode.js依存関係と、`shfmt`、`shellcheck`を用意します。

```bash
npm install
brew install shfmt shellcheck
```

Markdownなどを変更した場合は、リポジトリ標準の検証を実行します。

```bash
./scripts/agent-docs-check.sh
```

## ビルドと配布

UniversalアプリとDMGを作成するには、次を実行します。

```bash
./scripts/build-app.sh
```

成果物は`dist/`に生成されます。スクリプトは、arm64とx86_64向けのリリースビルド、`.app`の組み立て、アドホック署名、DMG作成、SHA-256チェックサムの表示まで行います。

リリース時にバージョンを上げてビルドする場合は、更新幅を指定できます。引数を省略するとパッチバージョンを上げます。

```bash
./scripts/patch-build.sh
./scripts/patch-build.sh minor
./scripts/patch-build.sh major
```

`patch-build.sh`はバージョンを管理するソースファイルを更新し、アプリを起動して、`dist/sha-256.txt`を生成します。配布方針の詳細は[ビルド・署名・配布](docs/design-docs/70-packaging/build-and-distribution.md)を参照してください。

## 構成

| パス                         | 役割                                  |
| ---------------------------- | ------------------------------------- |
| `Sources/MultiTimerCore/`    | UIやOSに依存しないタイマーのロジック  |
| `Sources/MultiTimerStorage/` | JSON形式の永続化                      |
| `Sources/MultiTimerApp/`     | SwiftUI、通知、音、ウィンドウ制御     |
| `Tests/`                     | Coreの単体テストとStorageの結合テスト |
| `docs/design-docs/`          | 要件、仕様、設計、テスト、配布の正本  |
| `scripts/`                   | 開発起動、検証、ビルド、DMG作成       |

依存方向や各レイヤーの責務は[モジュール構成](docs/design-docs/40-architecture/module-structure.md)を参照してください。

## データ保存

タイマーのタイトルと設定時間は、次のJSONファイルに保存されます。

```text
~/Library/Application Support/multi-timer/timer.json
```

残り時間、実行中の状態、終了後の黄色表示は保存されません。保存されたJSONが破損している場合は、ファイルを同じディレクトリへ退避し、空の状態で起動します。
