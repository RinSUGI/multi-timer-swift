# フェーズ 5: UI 層（SwiftUI ビュー・スケーリング・ドラッグ）

`MultiTimerCore` の状態と Platform 実装を SwiftUI で結び、仕様どおりの見た目・操作を実現する。

## 前提

- 仕様の正本は `docs/design-docs/50-ui/layout-and-style.md`。配色・寸法・フォントはここと `Constants.swift` を正とする。
- ロジックは Core に置く。ビューは Core の状態を束縛し、ボタン活性・色・表示整形は Core の関数を使う（UI に判定ロジックを重複させない）。
- スケーリングは `GeometryReader` + Environment 配布（`docs/design-docs/50-ui/layout-and-style.md` の OQ-08）。

## ステップ 5.1 ビューモデルと状態束縛

- 対象ファイル: `Sources/MultiTimerApp/UI/TimerListViewModel.swift`、`TimerCardViewModel.swift`（名称は調整可）
- 実装内容
  - タイマー配列を保持し、`TimerStore`（フェーズ 3）と結ぶ。起動時 `load()`、追加・削除・編集確定・Clear で保存を呼ぶ。
  - 保存タイミング（`docs/plans/00-plan-overview.md`）: タイトルは 300ms デバウンス、セグメント確定と Clear は即時、追加・削除は即時。削除時は保留中のタイトルデバウンス保存を解除してから削除する。
  - 実行中タイマーの計時は、モデル層の `Timer`（RunLoop、間隔 200〜250ms、`tolerance` 設定）で駆動する。周期タイマーは実行中のタイマーにのみ持たせ、停止中は動かさない。tick は `Clock` 差分で `remainingMs` を更新し、0 到達で Core の自動リセット手順（黄色 true・終了処理発火・設定へ戻す）を呼ぶ。
  - 終了処理では Platform の `ChimePlaying` / `NotificationScheduling` を発火する（`Ports` 経由で注入）。
- 完了条件: ビューモデルが Core・Storage・Platform を結び、`swift build` が通る。
- 検証: `swift build`。

## ステップ 5.2 タイマーカード View

- 対象ファイル: `Sources/MultiTimerApp/UI/TimerCardView.swift`
- 仕様: `docs/design-docs/50-ui/layout-and-style.md` の「タイマーカードの構造」。
- 実装内容（上から順に）
  - タイトル行: 中央のタイトル入力欄（プレースホルダ「タイトル」、最大 50 文字、下線のみ・中央寄せ）+ 右端に赤い丸「×」削除ボタン。タイトルは実行中でも編集可能（`docs/design-docs/20-spec/timer-behavior.md`）。
  - 時刻表示: `HH:MM:SS`。各セグメントはクリック／フォーカスで編集開始（`Enter`/`Space`）、`:` は区切り。太字・大きめ。実行中は編集不可の見た目（disabled 相当）。黄色表示は `expiredAfterCountdown == true` のときのみ `#ffd60a`、それ以外は白。
  - セグメント編集: 入力は数字のみ（非数字は除去）、最大 2 桁、初期表示は現在値 2 桁ゼロ埋め・全選択。キー操作は仕様どおり（`docs/design-docs/20-spec/time-editing.md`）。
    - `Enter` 確定 / `Escape` キャンセル（元に戻す）。
    - `Tab`/`Shift+Tab` は端で巡回。`←`/`→` は端で止まる（巡回しない）。
    - 別セグメント編集開始・フォーカス外し・外側クリックで確定。
    - 確定時は Core の確定処理（残り基準で合成、`remainingMs`/`configuredMs` 更新、黄色解除、即時保存）。
  - ボタン列: Start / Stop / Reset / Clear を横並び。色は `Constants`（Start 緑・Stop 赤・Reset 青・Clear グレー）。活性・非活性は Core のボタン活性計算に従う。無効時は不透明度を下げカーソルを標準に戻す。
  - Reset は編集中セグメントを破棄、Start は確定してから動作（`docs/design-docs/20-spec/timer-behavior.md`）。
- 完了条件: 1 枚のカードが仕様どおり描画・操作でき、`swift build` が通る。
- 検証: `swift build`。目視は `swift run` または フェーズ 7 の `.app`。

## ステップ 5.3 リスト・追加パーツ・バージョン表示

- 対象ファイル: `Sources/MultiTimerApp/UI/RootView.swift`、`AddTimerView.swift`
- 仕様: `docs/design-docs/50-ui/layout-and-style.md`、`docs/design-docs/20-spec/multi-timer.md`。
- 実装内容
  - 縦 1 列: タイマー群 → 追加パーツ → バージョン表示。タイマー間に区切り線は入れない。収まらない場合は縦スクロール（`ScrollView`）。
  - 追加パーツ: 区切り線（敷居線）+ プラスマーク（＋）。領域全体がクリック対象。クリック／フォーカスで `Enter`/`Space` により追加。追加は末尾に `新規タイマーN`（採番は Core）・`configuredMs = 0`・新規 UUID、即時保存、追加後スクロールして見えるようにする。
  - 上限 12 到達時は追加パーツを淡色にして無効化する。
  - バージョン表示: 下部に `v<version>`（`Constants` の `appVersion`）を小さく淡色で。
  - 空状態: 起動時 0 件なら空タイマー（`title = ""`・`configuredMs = 0`）を 1 つ表示し、表示順と保存順を一致させるため即保存する（`docs/design-docs/20-spec/multi-timer.md`）。この初期化は App 結線（フェーズ 6）と重複しないよう、どちらか一方に置く（推奨: ビューモデルの初期ロード時）。
- 完了条件: リスト・追加・削除・空状態・バージョン表示が動作し、`swift build` が通る。
- 検証: `swift build`。目視は `swift run` または `.app`。

## ステップ 5.4 スケーリング（レスポンシブ）

- 対象ファイル: `Sources/MultiTimerApp/UI/Scaling.swift`（Environment キー等）と各 View
- 仕様: `docs/design-docs/50-ui/layout-and-style.md` の「スケーリング」。
- 実装内容
  - ルートに `GeometryReader` を置き、ウィンドウ**短辺**の 1/100 を `vmin`（pt 値）として Environment 経由で配下へ渡す。
  - フォント・余白は `clamp(min, factor × vmin, max)` で算出する。値は `docs/design-docs/50-ui/layout-and-style.md` の「スケーリング」表を正とする（時刻表示 28.8〜192pt、ボタン 8.8〜17.6pt、タイトル 8.8〜17.6pt、いずれも pt）。
  - 実装は `ScaledSize` 名前空間にまとめる。「縮めるほど UI 全体が滑らかに縮む」体験になれば数値は微調整してよい。
- 完了条件: ウィンドウリサイズで全体が連動して縮小・拡大し、最小 120x100 でも破綻しない。
- 検証: `swift run` で目視。最終確認は BB-10（フェーズ 7）。

## ステップ 5.5 フォント・選択・カーソル

- 対象: 各 View
- 実装内容
  - 丸ゴシック相当（`.rounded` デザイン）を使い、日本語は丸ゴシックにフォールバック。
  - テキスト選択は基本無効。タイトル入力欄とセグメント入力欄でのみ入力・選択を許可。
- 完了条件: フォントが丸ゴシック系で、選択挙動が仕様どおり。
- 検証: `swift run` で目視。

## フェーズ 5 完了条件

- ボタン活性・黄色表示・表示整形が Core の関数に基づき、UI 側に判定ロジックを重複させていない。
- スケーリング・ドラッグ移動・空状態・採番・上限が仕様どおり。
