# 目的・背景・対象範囲

## この文書で決めること

Swift 再実装プロジェクトの目的、背景、対象範囲（やること・やらないこと）、および設計書全体で用いる用語を定義する。

## 背景

既存アプリ `_archive/multi-timer-mac` は、TypeScript + Electron 製の macOS 向けカウントダウンタイマーである。機能面は完成しており、社内配布して問題なく動作している。

一方で Electron の宿命として、常駐時のメモリ消費が概ね 100〜200MB と大きい。同等の処理をネイティブの Swift で実装すれば 10MB 程度に抑えられる見込みである。詳細は `_archive/multi-timer-mac/docs/backlogs/20260705_risks.md` を参照。

## 目的

- 既存アプリの機能・振る舞いを維持したまま、Swift ネイティブ実装に置き換える。
- 常駐メモリ消費を大幅に削減する（非機能要件は [10-requirements/non-functional.md](../10-requirements/non-functional.md) を参照）。
- 再実装にあたり、既存アプリには無かった単体テストを設計・導入し、リグレッションを検出できる状態にする。

## 対象範囲（やること）

- 既存アプリの全機能を Swift で再現する。機能の一覧は [10-requirements/functional.md](../10-requirements/functional.md) を参照。
- 既存の振る舞いを仕様として明文化する（[20-spec/](../20-spec/) 配下）。
- 純粋ロジックを単体テスト可能な形に分離し、テストを設計する（[60-testing/](../60-testing/) 配下）。
- ブラックボックステストのケースを整備する。
- macOS アプリとしてビルド・配布できる状態にする（[70-packaging/](../70-packaging/) を参照）。

## 対象外（やらないこと）

- 新機能の追加。既存機能の同等再現に集中し、機能拡張は本プロジェクトの範囲外とする。
- Windows / Linux 対応。macOS 専用のままとする。
- クラウド同期・アカウント・ネットワーク通信。既存同様、通信ゼロ・テレメトリ無しを維持する。
- 自動アップデート機構の新規実装。既存同様、バージョンをファイル名で管理する配布モデルを踏襲する。
- Apple Developer ID による署名・公証（notarization）の必須化。実現できれば望ましいが、本プロジェクトの完了条件には含めない（[70-packaging/](../70-packaging/build-and-distribution.md) を参照）。

## 実装主体と前提

- 実装は Claude（Sonnet 4.6）が担当する想定である。
- 本設計書は、実装前に作業詳細プランを立てるための入力となる。設計書に無い判断が必要になった場合は、既存実装を一次情報源として参照する。

## 用語集

| 用語                       | 定義                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| タイマー / タイマーカード  | 1 つのカウントダウン単位。タイトル・時刻表示・操作ボタンを持ち、独立して動作する。 |
| セグメント                 | 時刻表示 `HH:MM:SS` の「時」「分」「秒」それぞれの 2 桁部分。                      |
| 設定時間（`configuredMs`） | ユーザーが設定した基準時間。ミリ秒。リセット時の戻り先。永続化対象。               |
| 残り時間（`remainingMs`）  | 現在のカウントダウン残量。ミリ秒。永続化しない（起動時は設定時間に一致）。         |
| 自動リセット               | カウントダウンが 0 に到達し、通知後に設定時間へ自動的に戻る動作。                  |
| 時間切れ表示（黄色表示）   | 自動リセット後、数字を黄色で表示する状態。セッション内のみ保持。                   |
| 敷居線                     | 最下部のタイマー追加パーツにある区切り線。                                         |
| DB / ストレージ            | タイマーを保存する JSON ファイル（`timer.json`）。                                 |
