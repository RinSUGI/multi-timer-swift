# 永続化・データモデル

## この文書で決めること

タイマーの保存形式、保存場所、正規化、書き込みの直列化、破損対応、保存タイミングを定義する。

## 保存場所

- 保存先: `~/Library/Application Support/multi-timer/timer.json`。
- App Sandbox は有効にしない。有効にすると保存先がコンテナ（`~/Library/Containers/<バンドルID>/` 配下）に変わり、本書のパス前提が成立しなくなる。Mac App Store 配布は対象外のため、無効で問題ない。

## 保存形式

ファイルは次の JSON。

```json
{
  "timers": [
    {
      "id": "3de4d565-415d-4b89-8f6f-4634adb9907c",
      "title": "作業タイマー",
      "configuredMs": 1500000
    }
  ]
}
```

- `id`: タイマーの一意識別子（更新・削除の対象特定に使う）。
- `title`: タイトル（最大 50 文字）。
- `configuredMs`: 設定時間（ミリ秒、最大 `99:59:59`）。
- 配列の順序が画面上の並び順を表す（[20-spec/reordering.md](../20-spec/reordering.md)）。並び順のための項目は持たない。

保存するのはこの 3 項目のみである。残り時間・実行中・黄色状態は保存しない。したがって再起動時、各タイマーは「残り時間 = 設定時間・非実行・白」で復元される。

## 定数

| 定数           | 値                                     | 意味             |
| -------------- | -------------------------------------- | ---------------- |
| 最大タイトル長 | 50 文字                                | 超過分は切り詰め |
| 最大設定時間   | `(99*3600 + 59*60 + 59) * 1000` ミリ秒 | `99:59:59`       |
| 最大タイマー数 | 12                                     | 超過分は切り捨て |

- これらは UI 側と共有する単一の定義とする（[10-requirements/non-functional.md](../10-requirements/non-functional.md) の NFR-08 を参照）。

## 正規化

1 件のタイマーを正規化する規則（`normalizeTimer` 相当）。

- 入力がオブジェクトでなければ、その要素は無効として捨てる（`null` を返す）。
- `id`: 非空文字列ならそのまま。そうでなければ新規 UUID を採番する。
- `title`: 文字列なら先頭 50 文字に切り詰め。そうでなければ空文字。
- `configuredMs`: 有限数なら `floor` して `[0, 最大設定時間]` にクランプ。そうでなければ 0。

## パースと補正（`parseTimers` 相当）

- 正常形式: `{ timers: [...] }`。各要素を正規化し、無効な要素（`null`）を除外し、先頭 12 件に切り詰める。
- 単一オブジェクト形式（`{ title, configuredMs }`）を検出した場合は、1 件の配列として読み込む。JSON を手で編集した場合などの緩い入力に耐えるための保険。
- 「読み込み内容と保存内容が食い違ったため書き戻しが必要」なとき、`ParseResult.migrated = true` を返す。名前は「読み込み時点のファイル内容から現行形式へ書き換えた」ことを指す。次のいずれかで真になる。
  - 要素数が 12 を超えていた。
  - `id` を持たない要素があり、採番で補った。
  - 単一オブジェクト形式だった。
- `migrated = true` の場合、正規化後の内容でファイルを書き戻す。

## 破損対応

読み込み時の異常は次のように扱う（アプリが起動不能にならないことを最優先とする。NFR-05）。

- ファイルが存在しない（ENOENT 相当）: 空配列を返す。エラーとしない。
- 読み込み自体の失敗（存在するが読めない等）: ログに記録し、空配列を返す。
- JSON パース失敗（クラッシュ・電源断で書き込み途中になった等）: 破損ファイルを退避してから空配列を返す。
  - 退避先: 同ディレクトリの `timer.corrupt-<タイムスタンプ>.json`。
  - 退避に失敗してもログに記録し、空配列で継続する。

## 書き込みの直列化

- 保存・削除・読み込みは直列に実行する。
- 理由: 複数の保存が「読み込み → 配列更新 → 書き込み」の 3 ステップで同時に走ると、互いに上書き・混入して壊れた JSON を生む。
- シリアルな `DispatchQueue` または `actor` で全ファイル操作を直列化する（[40-architecture/technology-choices.md](../40-architecture/technology-choices.md) を参照）。

## 保存操作の意味

- 保存（`TimerStore.save(_:)`）: 入力を正規化し、現在のファイルを読み、`id` 一致があれば更新、無ければ末尾に追加し、12 件に切り詰めて書き込む。
- 削除（`TimerStore.delete(id:)`）: ファイルを読み、`id` 一致を除外し、変化があれば書き込む（変化が無ければ何もしない）。
- 並び順の保存（`TimerStore.reorder(ids:)`）: ファイルを読み、要素を `ids` の順に並べ替え、変化があれば書き込む（変化が無ければ何もしない）。並べ替えの規則は次のとおり。
  - `ids` に含まれる要素を `ids` の順に並べる。
  - `ids` に含まれない要素（UI 側がまだ知らない要素）は捨てず、元の相対順を保って末尾に置く。
  - ファイルに存在しない `id` は無視する。
  - `ids` 内の重複は先に現れたものだけを採用する。
  - 要素の内容（`title`・`configuredMs`）は変えない。並び順だけを変える。
  - 並べ替えの規則は純粋関数として Core に置く（[60-testing/unit-test-design.md](../60-testing/unit-test-design.md) の TC-Order）。

## 保存タイミング

| きっかけ             | タイミング                                       |
| -------------------- | ------------------------------------------------ |
| タイトル入力         | 入力が止まってから 300ms 後に 1 回（デバウンス） |
| セグメント編集の確定 | 確定時に即時保存                                 |
| Clear                | 実行時に即時保存                                 |
| タイマー追加         | 追加時に即インサート                             |
| タイマー削除         | 削除時に即削除                                   |
| 並び替え             | ドロップで並び順が変わったときに即時保存         |

- デバウンスは、素早い連続入力のたびにファイル書き込みが走るのを防ぐ。
- タイマー削除時は、保留中のデバウンス保存をキャンセルしてから削除する。
- 並び替えは保留中のデバウンス保存をキャンセルしない。タイトル保存は `id` 一致で更新するため、並び順を崩さない。
- 並び順の保存は UI が保持する全タイマーの `id` 列を渡す。追加の直後に並び替えた場合などで、インサートより先に並び順の保存が実行されても、その `id` は無視され、続くインサートで末尾に入る。このとき画面とファイルの並び順がずれるが、次の並び替えで解消する。ドラッグ操作は追加から十分に時間が空くため、実用上は起きない前提とする。
