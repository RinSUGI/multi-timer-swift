# 非機能要件

## この文書で決めること

本アプリが満たすべき性能・品質・運用上の非機能要件を定義する。軽量なネイティブアプリであることが主眼である。

## NFR-01 メモリ消費（最優先）

- アイドル常駐時の実メモリ（フットプリント）を 10〜30MB 程度に抑える。
- 測定方法: アクティビティモニタの「メモリ」列、または `footprint` / `vmmap` コマンドで、タイマー 1 個表示・非実行のアイドル状態を計測する。
- 判定基準は [Open Questions](#open-questions) の OQ-02 を参照。

## NFR-02 CPU 消費

- カウントダウン実行中の CPU 使用を、実用上無視できる水準に抑える。
- 方針: 画面更新間隔は 200〜250ms 程度で十分とし、残り時間の計算は経過時刻（wall-clock）から算出して更新頻度と精度を分離する。詳細は [40-architecture/technology-choices.md](../40-architecture/technology-choices.md) を参照。
- ウィンドウが非表示・非アクティブのときは、可能なら更新頻度をさらに落とす。

## NFR-03 起動時間

- ダブルクリックからウィンドウ表示までを、体感で即時（1 秒以内を目安）とする。
- 初回のタイマー終了時に「最後の 1 秒が長く感じる」現象（音声サブシステムの初回起動遅延に起因）を起こさないこと。対策は [20-spec/notification-and-sound.md](../20-spec/notification-and-sound.md) を参照。

## NFR-04 セキュリティ・プライバシー

- ネットワーク通信を一切行わない。テレメトリを持たない。
- 保存する情報はタイマーのタイトルと設定時間のみとする。
- 外部から取得したコードや URL を実行・読み込みしない。

## NFR-05 データ堅牢性

- 保存ファイルが破損しても、アプリが起動不能にならないこと。破損時は破損ファイルを退避し、空の状態で起動する。詳細は [30-data/persistence.md](../30-data/persistence.md) を参照。
- 並行する保存・削除・読み込みが競合しても、ファイルが壊れないこと（書き込みの直列化）。

## NFR-06 対応 OS

- 対応 OS の下限は macOS 13（Ventura）以上とする。
- Apple Silicon と Intel の両方で動作すること（Universal 配布）。

## NFR-07 テスト容易性

- 純粋ロジック（時刻変換・状態遷移・正規化）を UI から分離し、単体テストできる構造にする。
- 詳細は [60-testing/unit-test-design.md](../60-testing/unit-test-design.md) を参照。

## NFR-08 保守性

- 設定値（上限個数・最大文字数・最大時間）はコード内の単一箇所で定義し、UI 側とストレージ側で重複させない。共有定数として 1 箇所にまとめる。

## Open Questions

- OQ-02 メモリ目標値 10〜30MB の許容上限を、どこで「合格」とみなすか。実測後に確定する。
  - 決定: アイドル常駐（タイマー 1 個・非実行）の footprint 30MB 以下を合格とする。実測が 15MB 前後に収まればそのまま確定し、30MB を超えた場合のみ原因を調査する。実装前に決めなくてよい（実測後で足りる）。測定〜対応をバックログとして残す。
