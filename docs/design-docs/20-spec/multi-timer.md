# 複数タイマーの追加・削除・上限

## この文書で決めること

複数タイマーの並列管理、追加、削除、上限、および空状態の扱いを定義する。並び替えは [reordering.md](reordering.md) を正本とする。

## 並列管理

- タイマーは縦に並び、各々が独立してカウントダウン・通知・保存する。
- タイマー間に区切り線は入れない。
- ウィンドウに収まらない場合は縦スクロールする（[50-ui/layout-and-style.md](../50-ui/layout-and-style.md) を参照）。
- 画面上の並び順は、保存されている順序と一致させる。追加は末尾に append する。
- ユーザーはドラッグで並び順を変えられる。詳細は [reordering.md](reordering.md) を参照。

## タイマーの追加

- 最下部に「追加パーツ」を置く。区切り線（敷居線）と、その下のプラスマーク（＋）からなる。
- この領域をクリック、またはフォーカスして `Enter` / `Space` で追加する。Start などと同種のボタンにはしない。
- 追加されるタイマー。
  - `id`: 新規 UUID。
  - `title`: `新規タイマーN`。N は後述の採番規則による。
  - `configuredMs`: 0。
- 新規タイマーは既存の末尾に追加する。
- 追加した時点で DB にインサートする（[30-data/persistence.md](../30-data/persistence.md) を参照）。
- 追加後、そのタイマーが見えるようスクロールする。

### `新規タイマーN` の採番

- 既存タイマーのタイトルのうち `新規タイマー<数字>` に一致するものから最大の数字を求め、その `+1` を N とする。
- 一致するものが無ければ N = 1。

## 上限

- タイマーの上限は 12 個。
- 上限に達したら追加パーツを無効化し、追加操作を受け付けない。
- 上限値は UI 側とストレージ側で共通の定数として 1 箇所に定義する（[10-requirements/non-functional.md](../10-requirements/non-functional.md) の NFR-08 を参照）。
- ストレージ側でも上限を超える分は切り捨てる（保険。[30-data/persistence.md](../30-data/persistence.md) を参照）。

## タイマーの削除

- タイトル右端に赤い丸の「×」ボタンを置く。
- クリックすると、そのタイマーを DB から物理削除し、画面からも取り除く。
- 削除前に、そのタイマーの計時ループと保存の遅延処理を停止する（[timer-behavior.md](timer-behavior.md) のリソース解放を参照）。
- ファイル自体は削除しない。他のタイマーが残ればその配列が、すべて削除すれば空配列 `{ "timers": [] }` が残る。

## 空状態の扱い

- 起動時に保存済みタイマーが 0 件だった場合、未指定の空タイマー（`title = ""`、`configuredMs = 0`）を 1 つだけ表示する。
- この空タイマーは、表示順と保存順を一致させるために起動時に即保存する。
- すべて削除した状態で再起動しても、この規則により空タイマーが 1 つ表示される。

## 独立動作の具体例

- タイマー A（1 秒）とタイマー B（2 秒）を同時に走らせた場合、A が終わったら A の通知音と通知が出て、B が終わったら B の通知音と通知が出る。
- 通知はまとめられず、終わった順にスタック表示される（[notification-and-sound.md](notification-and-sound.md) を参照）。

## 永続化との関係

- 追加は即インサート、削除は即削除、並び替えは確定時に並び順を即時保存。設定時間の変更（セグメント編集の確定・Clear）は即時保存、タイトル入力のみ 300ms デバウンス保存。
- 保存・削除・読み込みは直列化する。詳細は [30-data/persistence.md](../30-data/persistence.md) を参照。
