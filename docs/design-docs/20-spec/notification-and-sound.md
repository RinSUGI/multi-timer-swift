# 通知とチャイム音の仕様

## この文書で決めること

カウントダウン終了時のチャイム音と macOS 通知の仕様、および初回再生の遅延対策を定義する。

一次情報源: `_archive/multi-timer-mac/src/renderer/timer.ts`（`playChime` / `getAudioContext` / `warmUpAudio`）、`_archive/multi-timer-mac/src/main/main.ts`（通知）、`_archive/multi-timer-mac/docs/issues/20260705_02_notification.md`、`20260705_06_latency-of-initial-notification.md`。

## 終了時の一連の動作

タイマーが 0 に到達したとき、次を行う。

1. チャイム音を再生する。
1. そのタイマーのタイトルを添えて macOS 通知を表示する。

これらはタイマーごとに独立して発生する。

## macOS 通知

- タイトル: タイトルが空でなければ `<タイトル> 終了`、空なら `タイマー終了`。前後の空白は除去して判定する。
- 本文: `設定した時間が経過しました`。
- 複数のタイマーが相前後して終わった場合、1 つにまとめず、終わった順にスタック表示する。
  - 実装方針: 通知は個別に生成し、システムへ引き渡した後も参照を保持して早期解放されないようにする。既存版は `Set` で保持し、`close` / `click` で解放していた。Swift 版では `UserNotifications`（`UNUserNotificationCenter`）を用い、通知ごとに一意の識別子を与えてまとめられないようにする。
- 通知が OS 側で無効・非対応の場合は、音のみで静かに継続し、エラーにしない。

### 通知許可

- Swift 版では初回に通知の許可を要求する（`UNUserNotificationCenter` の `requestAuthorization`）。
- 許可されていない場合でもアプリは正常に動作し、音は鳴る。
- 利用者向けの許可手順は既存 README の「macOS の通知を有効にする」に相当する内容を踏襲する。

## チャイム音

- 「おぜ」を模した 2 音のチャイム（ヘ長調）。
  - 1 音目「お」= E: C メジャー和音（C4-E4-G4）+ メロディ E5。長さ約 0.45 秒。
  - 2 音目「ぜ」= D: B♭ メジャー和音（B♭3-D4-F4）+ メロディ D5。長さ約 0.90 秒。
- 音色: 基音に倍音（2 倍・3 倍）を重ねてピアノ風にする。既存の倍音比は基音 0.07 / 2 倍 0.02 / 3 倍 0.007。各音は立ち上がり後にゆるやかに減衰させる。

### 具体的な周波数（参考値）

| 音      | 和音とメロディ（Hz）              | 長さ（秒） |
| ------- | --------------------------------- | ---------- |
| お（E） | 261.63 / 329.63 / 392.00 / 659.25 | 0.45       |
| ぜ（D） | 233.08 / 293.66 / 349.23 / 587.33 | 0.90       |

### Swift 版での実装方針

- 音を厳密に再現したい場合、次のいずれかを選ぶ。
  - 方針 A: 上記の音を事前にオーディオファイル（`.caf` / `.aiff` など）へレンダリングしてバンドルし、再生する。実装が単純で遅延も小さい。
  - 方針 B: `AVAudioEngine` などで実行時に合成する。既存の音色パラメータを移植できるが実装量が増える。
- どちらを採るかは [40-architecture/technology-choices.md](../40-architecture/technology-choices.md) で決める。音の完全一致が難しい場合、「短い終了チャイムであること」を優先し、細部の一致は必須としない（[Open Questions](#open-questions) を参照）。

## 初回再生の遅延対策（重要）

既存版では、本番ビルドで「初めてタイマーが 0 に到達したときだけ、最後の 1 秒が長く感じる」現象があった。原因は、初回の `AudioContext` 生成が OS のオーディオデバイスを起動し、レンダラのメインスレッドを最大 1 秒ほど同期的にブロックしていたためである。

対策の考え方は次のとおり。

- 音声サブシステムを、カウントダウン終了パス上ではなく、事前に一度だけ暖機（ウォームアップ）しておく。
- 既存版は「ウィンドウ上での最初のクリック / キー入力」で 1 回だけ音声コンテキストを初期化していた。タイマーの設定・開始には必ずクリックかキー操作が伴うため、どのタイマーも 0 到達より前に暖機が済む。

Swift 版でも同様に、初回のユーザー操作時、あるいはアプリ起動直後の早い段階でオーディオ再生系を初期化し、終了時の再生が即座に返るようにする。詳細な選択は [40-architecture/technology-choices.md](../40-architecture/technology-choices.md) を参照。

関連する非機能要件は [10-requirements/non-functional.md](../10-requirements/non-functional.md) の NFR-03 を参照。

## Open Questions

- OQ-03 チャイム音を既存とビット単位で一致させる必要はあるか。事前レンダリング音源で近似する方針で良いか。
  - 決定: ビット一致は不要とし、方針 A（事前レンダリング音源）を採る。既存の合成パラメータ（周波数・倍音・エンベロープ）から音源ファイルを一度レンダリングすれば、聴感上は同一のチャイムを得られる。
