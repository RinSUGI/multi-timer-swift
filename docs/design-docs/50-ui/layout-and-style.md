# UI レイアウト・配色・スケーリング

## この文書で決めること

ウィンドウ、レイアウト、配色、フォント、レスポンシブなスケーリング、ドラッグ移動の仕様を定義する。

## ウィンドウ

| 項目         | 値                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------- |
| 初期幅       | 360px                                                                                         |
| 初期高さ     | 480px                                                                                         |
| 最小幅       | 120px                                                                                         |
| 最小高さ     | 100px                                                                                         |
| タイトルバー | 隠す（`titlebarAppearsTransparent = true` + `titleVisibility = .hidden`。信号機ボタンは残す） |
| 背景色       | `#1c1c1e`                                                                                     |

- ウィンドウはドラッグで自由にリサイズできる。縦横比の固定はしない。
- 上端の余白は最低 28px 確保し、macOS の閉じる・最小化・最大化ボタン（信号機）にコンテンツが重ならないようにする。

## ウィンドウを閉じたときの挙動

macOS 標準の作法に従う。

- ウィンドウを閉じてもアプリは終了しない（Dock に残る）。終了は `Cmd+Q`。
- Dock アイコンのクリックでウィンドウを再表示する。表示内容は保存データから復元されるため、閉じる前に実行中だったタイマーは失われる（終了通知も出ない）。
- 標準ショートカット（`Cmd+W` / `Cmd+Q`、テキスト入力欄でのコピー・ペースト）が効くよう、最小限のメインメニューを備える。

## 全体レイアウト

- 縦 1 列。上から順に、タイマー群 → 追加パーツ → バージョン表示。
- タイマー群は上端から縦に並ぶ。ウィンドウに収まらない場合は縦スクロールする。
- 各タイマーは「タイトル・時刻表示・ボタン列」を 1 グループとして配置する。
- コンテンツの最大幅の目安: タイマーカード・ボタン列は約 448pt、タイトル行は約 320pt を上限に中央寄せ。

## タイマーカードの構造

上から順に。

1. タイトル行: タイトル入力欄（中央）+ 右端に赤い「×」削除ボタン。
1. 時刻表示: `HH:MM:SS`。各セグメントは編集可能、`:` は区切り。
1. ボタン列: Start / Stop / Reset / Clear の 4 つを横並び。

- タイトル入力: プレースホルダは「タイトル」。最大 50 文字。下線のみの薄い見た目。中央寄せ。
- 時刻表示: 太字・大きめ。セグメントはホバーで薄い背景、実行中は編集不可の見た目。
- ボタン列: 4 ボタンは行いっぱいに等幅（`frame(maxWidth: .infinity)`）で並べ、常に 1 行に収める。ラベルは折り返さない（`lineLimit(1)`）。

### ボタンラベルの折りたたみ（狭幅時）

ウィンドウ幅が狭いと 4 つのボタンラベルが 1 行に収まらず、文字が折り返してボタンの高さが間延びしてしまう。これを避けるため、次の挙動とする。

- ウィンドウ幅が一定のしきい値（`ScaledSize.buttonLabelMinWidth` = 300pt）を下回ったら、ボタンのテキストラベルを隠し、代わりに機能を表す SF シンボルのアイコンを表示する。
  - Start = `play.fill`（▶）、Stop = `stop.fill`（■）、Reset = `arrow.counterclockwise`（↺）、Clear = `xmark`（✕）。
- アイコン表示・ラベル表示のどちらでも中身は 1 行に固定され、ボタンの高さは変わらない。
- しきい値の判定はウィンドウの **幅** のみで行う（`vmin` ではなく `geo.size.width`）。折り返しは幅で発生するため。
- しきい値はチューニング可能な単一の定数として持つ。

## 追加パーツ

- 最下部のタイマーの下に、区切り線（敷居線）とその下のプラスマーク（＋）を置く。
- この領域全体がクリック対象。ホバーで色が明るくなる。
- 上限（12 個）到達時は淡色にし、操作を無効化する。

## バージョン表示

- ウィンドウ下部に `v<version>` を小さく淡色で表示する。

## 配色

| 用途                 | 色                  |
| -------------------- | ------------------- |
| 背景                 | `#1c1c1e`           |
| 文字（標準）         | `#ffffff`           |
| 時間切れ（黄色表示） | `#ffd60a`           |
| Start ボタン         | `#34c759`（緑）     |
| Stop ボタン          | `#ff3b30`（赤）     |
| Reset ボタン         | `#007aff`（青）     |
| Clear ボタン         | `#8e8e93`（グレー） |
| 削除「×」ボタン      | `#ff3b30`（赤い丸） |
| タイトル文字         | 白 85% 不透明       |
| プレースホルダ       | 白 35% 不透明       |
| 区切り線・下線       | 白 20% 不透明       |

- ボタンは角丸。ホバーで不透明度が下がり、押下で軽く縮小するインタラクション。
- 無効なボタンは不透明度を大きく下げ、カーソルを標準に戻す。

## フォント

- 丸ゴシック系を優先する。指定順は次のとおり。
  - `SF Pro Rounded` → `Hiragino Maru Gothic ProN` → `ui-rounded` → `system-ui` → `sans-serif`。
- SwiftUI では丸ゴシック相当（`.rounded` デザイン）を使い、日本語は丸ゴシックにフォールバックする。

## スケーリング（レスポンシブ）

- 文字サイズ・ボタンサイズ・余白は、ウィンドウの短辺を基準に連動して縮小する。
- ウィンドウ短辺の 1/100 を `vmin`（pt 値）とし、フォントサイズや余白は `clamp(min, factor × vmin, max)` で算出する。実装は `ScaledSize`（`Sources/MultiTimerApp/UI/Scaling.swift`）に集約する。
- 主なスケール指定（値の単位はすべて pt）。

  | 対象               | 下限 | 係数 × vmin | 上限  |
  | ------------------ | ---- | ----------- | ----- |
  | 時刻表示のフォント | 28.8 | 18.0        | 192.0 |
  | ボタンのフォント   | 8.8  | 3.5         | 17.6  |
  | タイトルのフォント | 8.8  | 7.0         | 17.6  |

- ねらいは「ウィンドウを縮めるほど UI 全体が滑らかに縮む」体験である。

## ドラッグ移動

- 背景領域のドラッグでウィンドウを移動できる。
- ドラッグ対象外（操作領域）は次のとおり。
  - タイトル入力欄、削除ボタン。
  - 時刻表示（セグメント編集のクリックを奪わないため）。
  - ボタン列、追加パーツ、バージョン表示。
- SwiftUI では全面ドラッグ移動が標準では難しいため、`NSWindow.isMovableByWindowBackground` などを用い、操作要素がクリックを優先して受け取るようにする。

## 選択・カーソル

- テキスト選択は基本的に無効。タイトル入力欄とセグメント入力欄では入力・選択を許可する。

## Open Questions

- OQ-08 スケーリングの実現方法（GeometryReader によるスケール係数か、`ScaledMetric` か、独自計算か）。
  - 決定: ルートに `GeometryReader` を置き、ウィンドウの短辺から算出したスケール係数を Environment で配下ビューへ渡す。フォント・余白は「下限・係数 × 基準・上限」で計算する。
- OQ-11 ウィンドウを閉じたときの挙動: 「常駐（Dock に残る）」か「閉じたら終了」か。
  - 決定: 常駐とする。macOS 標準の作法であり、SwiftUI の既定挙動に近く追加実装が小さい。「ウィンドウを閉じてもカウントを継続して通知する」改善は技術的には可能だが、バックグラウンド処理の追加を伴うため本プロジェクトでは行わず、今後の改善候補として記録しておく。
