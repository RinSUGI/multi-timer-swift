# UI レイアウト・配色・スケーリング

## この文書で決めること

ウィンドウ、レイアウト、配色、フォント、レスポンシブなスケーリング、ドラッグ移動の仕様を定義する。

一次情報源: `_archive/multi-timer-mac/src/renderer/index.html`、`styles.css`、`src/main/main.ts`（ウィンドウ生成）。

## ウィンドウ

| 項目         | 値                                                    |
| ------------ | ----------------------------------------------------- |
| 初期幅       | 360px                                                 |
| 初期高さ     | 480px                                                 |
| 最小幅       | 120px                                                 |
| 最小高さ     | 100px                                                 |
| タイトルバー | 隠す（既存の `hiddenInset` 相当。信号機ボタンは残す） |
| 背景色       | `#1c1c1e`                                             |

- ウィンドウはドラッグで自由にリサイズできる。縦横比の固定はしない。
- 上端の余白は最低 28px 確保し、macOS の閉じる・最小化・最大化ボタン（信号機）にコンテンツが重ならないようにする。

## ウィンドウを閉じたときの挙動

既存版は macOS 標準の作法に従っており、Swift 版も踏襲する。

- ウィンドウを閉じてもアプリは終了しない（Dock に残る）。終了は `Cmd+Q`。
- Dock アイコンのクリックでウィンドウを再表示する。表示内容は保存データから復元されるため、閉じる前に実行中だったタイマーは失われる（終了通知も出ない）。これは既存版と同じ挙動である。
- 標準ショートカット（`Cmd+W` / `Cmd+Q`、テキスト入力欄でのコピー・ペースト）が効くよう、最小限のメインメニューを備える。

## 全体レイアウト

- 縦 1 列。上から順に、タイマー群 → 追加パーツ → バージョン表示。
- タイマー群は上端から縦に並ぶ。ウィンドウに収まらない場合は縦スクロールする。
- 各タイマーは「タイトル・時刻表示・ボタン列」を 1 グループとして配置する。
- コンテンツの最大幅の目安: タイマーカード・ボタン列は約 28rem、タイトル行は約 20rem を上限に中央寄せ。

## タイマーカードの構造

上から順に。

1. タイトル行: タイトル入力欄（中央）+ 右端に赤い「×」削除ボタン。
1. 時刻表示: `HH:MM:SS`。各セグメントは編集可能、`:` は区切り。
1. ボタン列: Start / Stop / Reset / Clear の 4 つを横並び。

- タイトル入力: プレースホルダは「タイトル」。最大 50 文字。下線のみの薄い見た目。中央寄せ。
- 時刻表示: 太字・大きめ。セグメントはホバーで薄い背景、実行中は編集不可の見た目。

## 追加パーツ

- 最下部のタイマーの下に、区切り線（敷居線）とその下のプラスマーク（＋）を置く。
- この領域全体がクリック対象。ホバーで色が明るくなる。
- 上限（12 個）到達時は淡色にし、操作を無効化する。

## バージョン表示

- ウィンドウ下部に `v<version>` を小さく淡色で表示する。

## 配色

| 用途                 | 色                  |
| -------------------- | ------------------- |
| 背景                 | `#1c1c1e`           |
| 文字（標準）         | `#ffffff`           |
| 時間切れ（黄色表示） | `#ffd60a`           |
| Start ボタン         | `#34c759`（緑）     |
| Stop ボタン          | `#ff3b30`（赤）     |
| Reset ボタン         | `#007aff`（青）     |
| Clear ボタン         | `#8e8e93`（グレー） |
| 削除「×」ボタン      | `#ff3b30`（赤い丸） |
| タイトル文字         | 白 85% 不透明       |
| プレースホルダ       | 白 35% 不透明       |
| 区切り線・下線       | 白 20% 不透明       |

- ボタンは角丸。ホバーで不透明度が下がり、押下で軽く縮小するインタラクション。
- 無効なボタンは不透明度を大きく下げ、カーソルを標準に戻す。

## フォント

- 丸ゴシック系を優先する。既存の指定順は次のとおり。
  - `SF Pro Rounded` → `Hiragino Maru Gothic ProN` → `ui-rounded` → `system-ui` → `sans-serif`。
- Swift（SwiftUI）では丸ゴシック相当（`.rounded` デザイン）を使い、日本語は丸ゴシックにフォールバックする。

## スケーリング（レスポンシブ）

- 文字サイズ・ボタンサイズ・余白は、ウィンドウの短辺を基準に連動して縮小する。既存は CSS の `vmin` + `clamp()` で実現していた。
- Swift 版では、ウィンドウサイズ（短辺）に応じてスケール係数を算出し、フォントサイズや余白へ反映する。下限・上限（`clamp` の役割）も設ける。
- 参考として既存の主なスケール指定。
  - 時刻表示のフォント: 下限 1.8rem、基準 18vmin、上限 12rem。
  - ボタンのフォント: 下限 0.55rem、基準 3.5vmin、上限 1.1rem。
  - タイトルのフォント: 下限 0.55rem、基準 7.0vmin、上限 1.1rem。
- 完全な数値一致は必須ではない。「ウィンドウを縮めるほど UI 全体が滑らかに縮む」という体験の再現を優先する。

## ドラッグ移動

- 背景領域のドラッグでウィンドウを移動できる（既存の全面 `-webkit-app-region: drag`）。
- ドラッグ対象外（操作領域）は次のとおり。既存の `no-drag` に相当する。
  - タイトル入力欄、削除ボタン。
  - 時刻表示（セグメント編集のクリックを奪わないため）。
  - ボタン列、追加パーツ、バージョン表示。
- SwiftUI では全面ドラッグ移動が標準では難しいため、`NSWindow.isMovableByWindowBackground` などを用い、操作要素がクリックを優先して受け取るようにする。

## 選択・カーソル

- テキスト選択は基本的に無効（`user-select: none` 相当）。タイトル入力欄とセグメント入力欄では入力・選択を許可する。

## Open Questions

- OQ-08 スケーリングの実現方法（GeometryReader によるスケール係数か、`ScaledMetric` か、独自計算か）。実装時に決める。
  - 決定: ルートに `GeometryReader` を置き、ウィンドウの短辺から算出したスケール係数を Environment で配下ビューへ渡す。フォント・余白は「下限・係数 × 基準・上限」で計算し、既存 CSS の `clamp()` + `vmin` と同じ意味論を保つ。実装時に確定すればよい。
- OQ-11 ウィンドウを閉じたときの挙動を既存どおり「常駐（Dock に残る）」とするか、「閉じたら終了」に単純化するか。本書は既存踏襲を既定とする。
  - 決定: 既存踏襲（閉じても常駐）とする。macOS 標準の作法であり、SwiftUI の既定挙動に近く追加実装が小さい。なお Swift 版では「ウィンドウを閉じてもカウントを継続して通知する」改善も技術的には可能だが、機能同等再現の方針（[00-overview/purpose-and-scope.md](../00-overview/purpose-and-scope.md)）に沿い本プロジェクトでは行わず、今後のバックログ対応として漏れないよう記録しておく。
